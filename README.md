# 学术论文写作与独立验收 技能 套件（简体中文版）

**版本：** 1.0.1  
**语言：** 简体中文为默认工作语言；支持按用户要求撰写英文论文  
**格式：** 兼容开放式 Agent Skills 文件夹约定

本套件是在英文版 `Academic Paper Writing & Audit Skills v1.0.1` 基础上制作的中文本土化版本。保留原有工作流程、事实约束、提问机制、独立验收机制和交接结构，同时增加中文学术术语、缩写、混合排版、中文科技论文表达和中文出版规范。

## 一、两个独立 技能

1. **`academic-paper-writing-zh` — 学术论文写作（中文版）**  
   负责研究理解、资料核验、写作前规划、用户确认、正式撰写、学术表达和写作阶段自检。

2. **`academic-paper-audit-zh` — 学术论文独立验收（中文版）**  
   负责独立审查、证据核验、研究计划符合性检查、逻辑审查、中文表达检查和独立验收报告。

两个 技能 分别拥有独立的 `SKILL.md`。默认使用简体中文交流、提问、解释和交付；文件夹名、技能 标识符、YAML 字段名、代码标识符和必要的技术名称保留英文，以兼容工具和技术生态。

## 二、标准交接文件

- `Prewriting_Dossier.md`：研究理解、用户确认、事实状态、批准的大纲、论点与证据关系。
- `Manuscript.md`：最终论文，统一以 Markdown（`.md`）交付。
- `Claim_Evidence_Matrix.md`：重要论点与证据来源的对应关系。
- `Independent_Audit_Report.md`：独立验收报告。

### Markdown 论文中的图表不得省略

Markdown 是交付格式，不是删减研究内容的理由：

- 保留所有必要的图、表、公式、算法、附注、图例、坐标轴、单位、样本量和来源标注。
- 有原始图片文件时，尽可能作为独立资源文件保留，并使用相对路径引用，例如：`![图2 总体流程](figures/figure-2.png)`。
- 图片无法提取时，必须保留带编号的明确占位说明，写明应包含的内容及缺失资源；不得静默删除。
- 数据表不得用笼统文字替代；有数据时应保留具体数值。
- 图题、表题、图注、表注和正文引用必须相互对应。

## 三、中文学术表达的核心原则

1. 中文是中文论文的默认表达语言。存在规范中文术语时，正文直接使用中文，不随意夹杂英文单词。
2. 专业术语优先采用全国科学技术名词审定委员会公布的规范名词、国家标准、行业标准和学科公认译名。
3. 必须说明的英文缩写，首次出现时优先采用：**中文名词（英文全称，英文缩写）**。例如：`有限元分析（finite element analysis，FEA）`。
4. 首次定义后，默认优先使用中文术语；只有在术语重复频繁、缩写确有必要且符合学科惯例时，才使用缩写。
5. 软件名、模型名、算法专名、变量、代码、标准编号、数据集注册名称和参考文献原始题名等，不为汉化而强行翻译。
6. 中文论文还要检查翻译腔、欧化长句、名词化堆叠、中英文混排、标点、数字、量纲、符号和术语一致性。
7. 目标期刊或会议的现行要求优先于通用规则。

详细规则见两个技能各自的 `references/中文学术表达规范.md`；本套件根目录的 `中文规范参考来源.md` 提供了官方标准查询入口和版本核对记录。

## 五、安装和使用

### Codex

将两个 技能 文件夹分别放入 Codex 可发现的 技能 目录，例如：

- 用户级：`$HOME/.agents/skills/`
- 仓库级：`<repo>/.agents/skills/`

保持文件夹名与 技能 的 `name` 一致。

### ChatGPT

在当前版本支持 Skills 的 ChatGPT 桌面端或工作区中，使用界面提供的导入/安装流程。不同 ChatGPT 产品端对独立 技能 的支持可能不同；网页端或移动端若不支持直接导入独立 技能，应使用当前产品提供的插件分发方式。

### 单独安装

本套件同时提供两个单独压缩包。每个单独压缩包只包含一个 技能 文件夹，适合单独分发或上传到支持单 技能 包的接口。不要将总套件压缩包当成一个 技能 上传。

## 六、文件说明

- `academic-paper-writing-zh_v1.0.1.zip`：单独的中文写作 技能。
- `academic-paper-audit-zh_v1.0.1.zip`：单独的中文独立验收 技能。
- `Academic_Paper_Skills_Kit_ZH_v1.0.1.zip`：包含两个 技能、模板、参考规范、质量测试用例的完整套件。

## 七、中文规范参考与适用边界

制作时核对了截至 2026 年 11 月可查的相关标准信息，主要包括：

- GB/T 7713.2—2022《学术论文编写规则》。
- GB/T 6447—2025《文献摘要编写规则》（2026 年 2 月 1 日实施）。
- GB/T 7714—2025《信息与文献 参考文献著录规则》（2026 年 7 月 1 日实施）。
- GB/T 15834—2011《标点符号用法》。
- GB/T 15835—2011《出版物上数字用法》。
- GB/T 3101—1993《有关量、单位和符号的一般原则》。
- CY/T 119—2015《学术出版规范 科学技术名词》。
- CY/T 170—2019《学术出版规范 表格》。
- CY/T 171—2019《学术出版规范 插图》。
- CY/T 173—2019《学术出版规范 关键词编写规则》。

标准状态可能更新。技能 要求在具体投稿或格式合规任务中重新核对官方标准状态、目标期刊最新投稿指南和适用版本；不得仅凭本 README 的版本清单宣称已满足所有期刊要求。推荐性标准、行业标准和期刊内部要求也不能混为一谈。

## 八、论断强度保护与防御性写作控制

v1.0.1 在不改变原有研究梳理、提问、大纲确认、正式写作和独立验收流程的前提下，增加了针对防御性写作的专项约束：写作阶段记录经批准且有证据支持的核心论断及其适用范围，不得为预防假想质疑而无依据地弱化论断或添加免责声明；审稿意见须先核验和筛选，不能自动进入正文。独立验收阶段则对照论断基准检查无依据弱化、撤回、重复限定和比例失当的免责声明。真实不确定性和研究局限仍须如实保留，目标是避免无依据夸大，也避免无依据退缩。

## 九、不需要自建 MCP

这两个 技能 是工作流程、规范和模板，不依赖自建 MCP、API 或额外脚本。它们会在当前环境具备相应能力时使用文件读取、联网搜索和其他可用工具；若某项能力不可用，必须说明核验边界，不得假装已完成核验。

## 十、适用范围

仅用于常见学术论文，包括原创研究论文、综述、系统综述、范围综述、理论/方法论文、短篇研究通讯、数据论文、软件论文和学术观点论文。不覆盖项目研究报告、商业报告、基金申请书或一般技术文档。

## 十一、设计依据

技能 文件夹结构遵循开放式 Agent Skills 约定：每个 技能 目录以 `SKILL.md` 为入口，使用 YAML 前置信息，并可包含 `references/`、`assets/` 和 `agents/openai.yaml`。技术字段和文件标识符保留英文，正文指令以中文为主。
