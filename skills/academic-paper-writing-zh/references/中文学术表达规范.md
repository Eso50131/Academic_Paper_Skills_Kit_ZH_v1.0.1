# 中文学术表达与中英文混排规范

## 1. 适用原则

本文件是中文学术论文的默认语言规范。它用于约束论文正文、摘要、图表题注、关键词、研究档案和验收意见。目标期刊、会议或学科明确要求与本文件不一致时，以经核实的目标要求为准。

核心原则：

- 中文论文以中文为主体语言。
- 英文只在术语辨识、专名、标准标识、公式、代码、原始文献元数据等确有需要时保留。
- 不以“少用英文”为目标而损害准确性；也不以“显得专业”为由滥用英文。
- 规范术语、概念准确和全文一致性优先于字面汉化。

## 2. 中文术语的选择顺序

对专业概念选择中文表达时，按以下优先顺序判断：

1. 全国科学技术名词审定委员会公布的规范名词及专业名词审定成果。
2. 现行国家标准、行业标准、技术规范和权威术语标准中的名称。
3. 目标学科高质量中文期刊和教材中的通行译名。
4. 若尚无稳定中文译名，使用准确的中文释义，并在首次出现时注明英文原文。
5. 若不同学科对同一英文术语有不同译法，依据本文研究领域和目标读者选定一种，并在全文统一。

可参考 CY/T 119—2015《学术出版规范 科学技术名词》。该规范强调优先采用规范名词，并区分规范名词、全称、简称、又称、俗称和曾称。使用异名时应有明确理由，不应在同一篇论文中随意切换。

不得：
- 仅凭机器翻译结果确定专业术语。
- 为避免重复而用不同译名指代同一概念。
- 将相近但不等价的术语混为一谈。
- 为了汉化而翻译软件、产品、算法注册名称或专有模型名。
- 将学科尚未统一的译名写成唯一标准答案。

## 3. 英文术语和缩写的首次出现格式

### 3.1 默认格式

首次出现且确有必要说明的英文缩写，原则上使用：

**中文名词（英文全称，英文缩写）**

例如：

- 有限元分析（finite element analysis，FEA）
- 检索增强生成（retrieval-augmented generation，RAG）
- 大语言模型（large language model，LLM）
- 图形处理器（graphics processing unit，GPU）
- 人工智能（artificial intelligence，AI）

括号内英文全称与缩写之间默认使用中文逗号“，”，以适应中文正文。若目标期刊明确要求半角标点或其他形式，则遵循目标期刊格式。

### 3.2 首次出现后如何使用

首次定义后，默认优先使用中文名词。例如：

> 本文采用有限元分析（finite element analysis，FEA）评价结构响应。后续章节均使用“有限元分析”这一中文术语。

只有在以下情况下才优先使用缩写：

- 该术语在正文中出现频率很高。
- 缩写在本学科中已被广泛接受。
- 使用缩写能明显改善句子可读性。
- 目标期刊或图表格式要求使用缩写。

不得每次出现术语都重复写英文全称，也不得在定义后无规律地交替使用中文全称、英文全称和缩写。

### 3.3 何时可以不写英文全称

如果缩写已属于目标学科高度公知、公认的通用表达，且目标期刊允许，可不再展开；但中文正文仍应优先给出中文名称。若缩写可能造成歧义，必须定义。

不能仅因为模型“觉得大家都知道”就省略定义。应结合读者范围和期刊规范判断。

### 3.4 缩写不应滥用

- 不要为短小、常用的中文术语另造英文缩写。
- 不要把每个方法模块都命名为英文首字母组合。
- 不要在标题中堆叠非公知缩写；除非目标期刊或领域惯例明确允许。
- 同一概念只能选用一套缩写，不得同时出现多个版本。
- 缩写的大小写、连字符和复数形式应保持准确。
- 缩写定义后，避免将中文后缀与缩写拼接成不规范的混合词；必要时使用“RAG 方法”“GPU 计算”等清晰形式，具体以期刊规范为准。

### 3.5 独立文本单元中的定义

摘要、正文、图表和附录可能被独立阅读。若摘要中首次出现非公知缩写，应在摘要内定义；正文也需要自明时，应按期刊要求在正文再次定义。图表能够脱离正文阅读时，应在图注或表注中解释其中不常见的缩写。

### 3.6 专名与软件名

软件、工具、模型、算法、数据集、硬件产品和机构名称应保留官方名称。例如 `OpenSeesPy`、`PyTorch`、`Transformer` 等不应凭空翻译成一个貌似正式的名称。

如有稳定中文译名，可使用“中文名称（官方英文名称）”。例如，数字对象唯一标识符（digital object identifier，DOI）。若名称本身就是专名且没有准确中文译名，直接保留英文专名即可，不要伪造英文全称。

## 4. 中文论文中应优先采用的常见表达

以下是表达选择示例，不是跨学科强制词典。专业语境不同，应选择准确译名。

| 不建议直接夹入正文的英文 | 优先考虑的中文表达 | 注意事项 |
|---|---|---|
| baseline | 基准方法、基线 | 依具体语境区分基准模型和比较基准 |
| pipeline | 处理流程、处理链 | 不必每次保留 pipeline |
| framework | 框架 | 有明确中文表达时直接使用 |
| dataset | 数据集 | 不必写成 dataset |
| fine-tuning | 微调 | 首次可按需要注明英文 |
| embedding | 嵌入表示、向量表示 | 需区分嵌入过程与向量结果 |
| ablation study | 消融实验 | 不必在中文正文重复英文 |
| benchmark | 基准测试、基准数据集 | 依据其具体功能选择 |
| performance | 性能、表现、评价指标 | 不可一律翻译成“性能” |
| robustness | 鲁棒性、稳健性 | 依据学科术语体系选择 |
| generalization | 泛化、泛化能力 | 不随意写成 generalization |
| inference | 推理、推断 | 结合机器学习或统计学语境 |
| deployment | 部署 | 直接使用中文 |
| feedback loop | 反馈闭环、反馈回路 | 先判断是否确实形成闭环 |
| workflow | 工作流程、处理流程 | 不必保留 workflow |
| module | 模块 | 直接使用中文 |
| metric | 指标、评价指标 | 具体说明指标含义 |
| accuracy | 准确率 | 不与精确度混用 |
| precision | 精确率/精度 | 结合统计或工程语境区分 |
| recall | 召回率 | 不与记忆、回忆混淆 |
| loss function | 损失函数 | 直接使用中文 |
| parameter | 参数 | 不必保留 parameter |
| hyperparameter | 超参数 | 直接使用中文 |
| sample | 样本 | 与样品等概念区分 |
| validation | 验证、确认 | 工程、统计和模型语境中含义可能不同 |

## 5. 避免翻译腔和欧化句式

中文学术表达应符合中文读者的理解习惯，不应把英文句子逐词转换成中文。

重点检查：

- 英文长定语直接前置，导致中文主干迟迟不出现。
- 连续使用多个“基于……的……”“针对……的……”“面向……的……”结构。
- 将简单动词改写成“进行……的实现/开展……的研究/实施……的分析”。
- 无必要地使用“被”字句。
- 句子缺少明确主语，连续多个分句依靠“其”“该”“此”连接。
- 用“在……方面具有……”代替具体动作或结果。
- 将英文连接词逐个翻译成“此外、同时、进一步、值得注意的是”。
- 为了看起来严谨而在一个句子中堆叠多层限定语。
- 过度使用“能够有效地”“实现了对……的提升”“具有一定的……意义”等空泛表达。

改写时优先恢复清晰的主语、谓语和对象，拆分过长句子，明确逻辑关系。不要为了追求“中文化”而损害必要的技术限定。

## 6. 中文标点和中英文混合排版

默认以 GB/T 15834—2011《标点符号用法》为中文正文标点依据；目标期刊有更具体规定时，以期刊要求为准。

- 中文叙述使用中文全角标点，如“，”“。”“；”“：”“（ ）”““ ””。
- 英文题名、代码、网址、DOI、公式和英文参考文献内部保留其原有标点。
- 不要在同一语义层级混用中文逗号和英文逗号。
- 中文括号与英文括号的使用应保持一致；术语定义默认使用中文全角括号。
- 句末标点的位置应与括号、引文、公式和图表编号的关系保持一致，并遵循目标期刊规则。
- 不要在中文句子中为了视觉效果随意加入英文斜杠、连字符或冒号。
- 中英文、数字与汉字之间是否留空格，应遵循目标期刊和学科惯例；没有明确规定时保持全文一致，不要机械地插入或删除所有空格。
- 代码、文件路径、命令、变量名和网址不得被中文标点破坏。

## 7. 数字、量、单位和符号

- 数字表达参考 GB/T 15835—2011《出版物上数字用法》，具体使用阿拉伯数字还是汉字数字应结合数字功能和语境，不要简单规定“所有数字都用阿拉伯数字”。
- 科学计量数据、公式、统计结果、编号、参数和实验测量值通常使用阿拉伯数字。
- 量、单位和符号应参考适用的国家/行业标准及学科规范；GB/T 3101—1993《有关量、单位和符号的一般原则》是相关基础文件，但使用前应核对其现行状态和后续修订。
- 物理量符号、单位符号和数学变量应区分；单位符号不随中文句子随意改变大小写。
- 不得将量的数值与单位混为一个变量，也不得混用不同单位制。
- 百分数、温度、角度、复合单位和上下标的具体排版应按适用标准及目标期刊处理，不在没有依据时硬编码统一空格规则。
- 公式中的拉丁字母、希腊字母、上下标和运算符保留数学写法，不因中文化而翻译。
- 正文中对符号的解释应与公式、图表和代码保持一致。

## 8. 中文摘要、英文摘要和关键词

### 中文摘要

- 摘要应独立、准确地概括论文内容，不应加入正文没有的结果或结论。
- 根据论文类型说明目的、方法、结果和结论；理论、综述和观点论文应采用适合其体裁的摘要结构。
- 避免“本文首先……其次……最后……”式目录介绍，除非摘要确实需要说明研究步骤。
- 摘要中首次出现的非公知缩写，应按目标期刊要求给出中文名称和英文全称/缩写。
- 摘要的篇幅、结构式/非结构式形式和要素应核对 GB/T 6447—2025 及目标期刊要求。

### 英文摘要

- 如果目标期刊要求英文摘要，应与中文摘要在研究对象、方法、数据、结果和结论上保持语义一致。
- 不做逐字直译；应使用规范英文术语和英语学术表达。
- 不得为了让英文摘要显得更有力度而扩大中文摘要中的结论。
- 专业术语和缩写应与正文一致。

### 关键词

- 关键词应表达论文核心主题，具有检索意义。
- 避免过于宽泛的词，如“方法”“理论”“分析”。
- 优先参考规范主题词、专业词表和目标期刊要求。
- 新兴领域尚无规范词时，可采用准确、稳定且具有检索价值的新术语。
- 关键词数量、分隔符和排列方式应核对 CY/T 173—2019 及目标期刊要求。

## 9. 图、表、公式和附注

- 中文论文中的图题、表题、图注和表注默认使用中文。
- 目标期刊要求中英文双语图题或表题时，按其格式提供。
- 图表中的术语、缩写、符号和单位应与正文一致。
- 图表应尽可能具有自明性；读者不依赖正文也能理解主要对象、条件和符号。
- 表格结构、插图内容和编排可参考 CY/T 170—2019《学术出版规范 表格》及 CY/T 171—2019《学术出版规范 插图》。
- 不得为汉化而修改原始数据、软件界面、实验设备标签或文献原图中的必要文字；可以在图注中解释。
- Markdown 转换不得丢失图表、公式、脚注、图例、附注或补充材料引用。

## 10. 参考文献和引文

- 中文论文正文可以使用中文引文叙述，但参考文献中的英文题名、作者、期刊名和出版信息应保留来源原文，不得自行翻译后替代原始书目信息。
- 引文格式和文后著录应按目标期刊要求执行。
- 目标期刊采用 GB/T 7714 时，应核对 GB/T 7714—2025；该版本自 2026 年 7 月 1 日起实施，不能默认继续使用 GB/T 7714—2015。
- 不得仅根据旧模板或文献管理软件默认格式判断当前规范。
- DOI、网址、卷期、页码和出版状态必须真实核对。

## 11. 最终中文表达检查清单

交付中文论文前逐项检查：

- [ ] 中文正文是否以中文为主体，是否存在不必要的英文单词。
- [ ] 有规范中文术语时，是否优先使用中文。
- [ ] 首次出现的必要英文缩写是否采用“中文名词（英文全称，英文缩写）”格式。
- [ ] 后续是否优先使用中文术语，缩写是否必要且统一。
- [ ] 软件名、模型名、算法专名和文献原题名是否被错误翻译。
- [ ] 同一术语是否出现多种译法。
- [ ] 是否存在逐词翻译、欧化长句、名词化堆叠和被动句滥用。
- [ ] 是否存在机械衔接词、空泛评价和不必要的“不是……而是……”结构。
- [ ] 中文标点、中英文混排、数字、单位和符号是否一致。
- [ ] 摘要、英文摘要和关键词是否准确且符合期刊要求。
- [ ] 图表标题、图注、表注、图例、坐标轴和单位是否清楚。
- [ ] 参考文献是否保留原始书目信息，并符合现行格式要求。
