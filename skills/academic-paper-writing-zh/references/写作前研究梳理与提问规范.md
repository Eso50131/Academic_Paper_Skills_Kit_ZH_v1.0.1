# 写作前研究梳理与提问规范

## 1. 目的

写作前研究梳理的目的是在正式撰写前，与用户建立对真实研究的一致理解。它不是通用登记表，也不是要求用户重复回答文件中已经明确的信息。

## 2. 先检查材料的工作顺序

1. 识别用户要求的写作模式和论文类型。
2. 清点与任务有关的文件和连接来源。
3. 提问前先阅读相关材料。
4. 提取事实、方法、结果、引用、图表和未解决问题。
5. 比较版本并识别矛盾。
6. 建立简明的不确定事项清单。
7. 只询问会实质影响研究描述、论文结构、证据或结论的问题。

面对大量文件时，可先进行主题检索或文档导航，再检查具体的一手资料。涉及代码和数据的论断，应在材料可用时检查相关代码、数据、日志或结果文件。不得把文件名或文件摘要当作未读内容的证据。

## 3. 研究简报字段

| 字段 | 需要记录的内容 |
|---|---|
| 论文信息 | 暂定题名、论文类型、学科、语言、目标期刊 |
| 研究对象 | 研究什么、研究尺度是什么 |
| 研究背景 | 理解问题所必需的背景 |
| 核心问题 | 论文具体要回答的问题 |
| 研究目标 | 研究希望实现或证明什么 |
| 研究范围 | 纳入的条件和明确排除项 |
| 已有研究 | 相关方法、证据、争议及来源状态 |
| 研究空白/问题 | 尚未解决什么，以及为什么重要 |
| 实际方法 | 已经实施的方法，而不是计划中的方法 |
| 数据/实验 | 数据来源、样本、条件、对照、指标 |
| 结果 | 实际结果及其来源 |
| 研究贡献 | 新能力、新发现、新方法、新证据或新解释 |
| 适用边界 | 假设、适用条件、局限和已知失效情况 |
| 未知事项 | 缺失或冲突的事实，以及后续处理方式 |

## 4. 第一轮：研究理解

检查材料后，通常提出 5—10 个归纳问题。不得为了凑数而提问，也不得询问材料已经回答的问题。

建议覆盖以下方面：

1. **论文定位：** 计划写哪一类学术论文？学科、语言、目标期刊和读者是什么？
2. **研究对象与背景：** 具体研究什么？研究对象或系统的哪些条件在范围内？
3. **核心问题：** 研究试图解决什么具体科学或技术问题？
4. **目标与范围：** 希望得出什么结论？哪些内容不在研究范围内？
5. **实际方法：** 实际使用了哪些方法、模型、算法、理论或程序？
6. **数据与实验：** 使用什么数据、样本、实验条件、基线方法、对照和指标？
7. **实际发现：** 已经得到什么结果？包括负面、无显著差异、混合和意外结果。
8. **研究贡献：** 用户认为新在哪里？有什么证据支持？

必要时使用简短子问题补充，但主问题应简洁。允许用户回答“未知”“尚未开展”或“不适用”。不得将尚未完成的工作暗示为已完成。

## 5. 第二轮：针对性核实

第一轮结束后，将用户回答与原始材料及初步论点—证据矩阵对照。只对仍然存在且影响较大的问题进行第二轮提问。

可涉及：

- 模型架构、组件、输入输出、损失函数、假设和参数设置。
- 方法选择的依据，以及备选方法是否真正测试过。
- 实验设计、基线、比较公平性、对照、重复次数和统计分析。
- 结果来源、计算、分母、阈值和失败情况。
- 作用机制究竟是测量所得、理论推导还是推测。
- 与已有代表性研究的区别。
- 泛化范围和未测试条件。
- 应突出哪项贡献，哪些内容应弱化或删除。
- 论文、代码、日志、表格和用户陈述之间的冲突。

仍可按需提出 5—10 个归纳问题，但只有存在相应数量的重要不确定事项时才提出这么多。不得重复第一轮。若只剩一两个关键问题，就只问一两个。

## 6. 两轮后仍有未知事项

两轮是常规研究理解设计，不是必须在两轮后强行得到全部答案。如果关键内容仍然缺失：

- 请求具体文件或用户明确确认。
- 标记为未解决。
- 缩小或限定论文论断。
- 用户希望先出草稿时，保留明确的待补充标记。
- 不得静默推断缺失事实。

复杂研究可能需要后续专项澄清。应解释为什么需要继续确认，而不是隐藏不确定性。

## 7. 论点—证据矩阵

正式撰写前建立矩阵。每项重要论断至少记录：

- 唯一编号。
- 准确或简洁的论断表述。
- 论断类别：背景、已有研究、方法、数据、结果、解释、创新性或结论。
- 证据来源及准确位置。
- 核验状态。
- 适用范围和限定条件。
- 计划写入的章节。

论断状态可为：

- 用户已确认但尚未独立核验。
- 已检查的一手证据支持。
- 证据只支持有限范围。
- 待核验。
- 无支持依据或存在矛盾。

## 8. 大纲与用户确认节点

正式撰写前向用户提交：

1. 论文类型、学科和写作定位。
2. 一段话说明论文中心论点。
3. 叙事主线：问题 → 已有研究 → 研究空白 → 方法/论证 → 证据 → 解释 → 结论。
4. 详细章节和小节大纲。
5. 各节的写作目的、关键论断、证据和衔接关系。
6. 论点—证据矩阵。
7. 尚未解决的事实及处理建议。

请用户确认或修改研究简报和大纲。只有明确确认后才开始完整撰写。用户要求豁免确认时，应记录豁免，不得把未知事实升级为已确认事实。

## 9. 研究档案交接

完成 `assets/Prewriting_Dossier_Template.md`。至少包括：

- 结构化研究简报。
- 已批准大纲及版本。
- 第一轮、第二轮提问及用户对重要事实的回答。
- 重要事实尽可能保留用户原话或忠实摘录。
- 用户对人工智能早期理解的修正。
- 未解决事项和明确排除的论断。
- 来源清单和证据矩阵。
- 用户批准状态和日期/版本。

默认不复制整段聊天记录。结构化记录更便于验收。对重要事实，应保留相关原始用户表述，不得在总结中抹去原有歧义。

## 10. 根据任务范围采用简化流程

- **仅语言校对：** 不启动完整访谈；保留原意，单独标出疑似事实问题。
- **单节撰写：** 检查该节相关证据，只询问该节关键缺失事实。
- **仅大纲任务：** 大纲和用户确认完成后停止，不擅自撰写全文。
- **完整论文：** 除非用户明确豁免，否则完成全部流程。
