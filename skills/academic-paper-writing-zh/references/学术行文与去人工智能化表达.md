# 学术行文、论证与去人工智能化表达

## 1. 总原则

写作应让专业读者清楚理解：

- 作者提出什么论断。
- 该论断为什么重要。
- 有什么证据支持。
- 证据如何导向相应解释。
- 结论在什么条件下成立。

学术质量不等于正式词汇、冗长篇幅、华丽表达或完美对称的结构。

## 2. 段落层面的论证

一个段落应有一个主要表达任务。可用以下思路检查：

1. **论点/主题：** 本段要建立什么观点。
2. **证据：** 数据、理论、文献、方法细节或案例。
3. **推理：** 为什么这些证据支持该观点。
4. **意义/衔接：** 由此得到什么含义，或下一段需要解决什么。

这是一种论证检查方式，不是必须写成四句话的模板。有的段落只需提出观点并给出证据；有的段落需要更多解释。

相邻段落应形成有意义的逻辑序列，而不是若干相关事实的集合。

## 3. 句子的信息组织

Gopen 和 Swan 关于读者预期的研究写作建议值得参考：在适当情况下，句子可以从读者熟悉的背景信息切入，将真正重要的新信息放在句末等容易获得强调的位置。应灵活使用，不要机械套用。

- 让句子的主语与主要谓语保持清晰关系。
- 不要把多个无关论断塞进一个长句。
- 连续论述同一问题时，保持主题和逻辑对象稳定。
- 先引入新概念，再使用该概念展开论证。
- 将关键的新信息放在容易识别的位置。
- 根据论证需要变化句长，不设置僵硬的字数限制。

## 4. 不同章节的表达任务

### 引言
从理解研究问题所需的最少背景出发，尽快进入具体问题。综合相关文献，提出有依据的研究空白，说明研究目标和贡献。避免与研究问题无关的泛泛历史背景。

### 文献综述
按研究问题、方法类别、理论、证据或有意义的时间线组织。使用共同维度比较研究，解释分歧和局限。避免逐篇论文摘要式罗列。

### 方法
描述实际完成的工作，并提供理解或复现所需的信息。相关时说明假设、数据、参数、模型、指标和程序。不要写成研发过程日记。

### 结果
准确报告观测发现，区分观察与解释，保留负面、无显著差异和混合结果。不得只挑选有利结果。

### 讨论
解释结果，与已有研究比较，分析可能机制，讨论意义和局限，避免超出证据范围。

### 结论
回答研究问题，说明有证据支持的贡献及边界。不得引入新结果，也不得逐节重复摘要。

## 5. 常见人工智能化表达及改进方式

不要机械禁用某个词，而应判断它是否承担真实的逻辑功能。

| 常见弱表达 | 问题 | 改进方式 |
|---|---|---|
| “随着……的快速发展” | 泛化铺垫 | 直接从具体研究背景或问题切入 |
| 反复使用“并非……而是……”“不仅……而且……” | 人为制造对照 | 直接说明方法、事实或真正存在的区别 |
| 每段都用“首先、其次、最后” | 机械排序 | 仅在内容确有顺序关系时使用 |
| “值得注意的是……” | 延迟表达重点 | 直接陈述发现 |
| 反复使用“综上所述”“总而言之” | 重复总结 | 直接给出综合判断，或删除 |
| “先进、高效、全面、系统、显著” | 用评价词替代证据 | 说明具体指标、比较对象、范围和结果 |
| “提供了新的思路” | 贡献模糊 | 具体说明新增了什么方法、能力、证据或认识 |
| “奠定了坚实基础” | 常为空泛表达 | 说明具体可复用成果或实际意义 |
| 长篇解释被放弃的方法 | 变成决策日记 | 只保留影响有效性、可复现性、公平性或解释的选择 |
| 每段长度和句式完全一致 | 节奏僵硬 | 让段落结构服从论证需要 |
| 抽象名词过多 | 隐藏行动主体和动作 | 使用具体主语、动词和对象 |
| 为避免重复而不断换术语 | 破坏概念一致性 | 保持定义术语稳定 |
| 所有结果都写成正面 | 扭曲研究事实 | 如实报告负面、无显著差异和混合发现 |

### 5.1 “不是……而是……”并非绝对禁用

只有在以下情况才使用对照：

- 纠正常见误解。
- 区分读者容易混淆的概念。
- 明确研究范围。
- 说明相对于已有研究的实质区别。

不得仅为了让简单陈述显得深刻而人为制造对照。

### 5.2 不要叙述无关的备选方案淘汰过程

以下情况可以说明被选方法及其原因：

- 备选方案是公认基线方法。
- 系统比较本身就是研究内容。
- 方法选择会实质影响有效性或解释。
- 读者需要该理由才能复现方法。
- 排除某种方案会改变研究范围或结论普适性。

通常应省略：

- 作者私下考虑但没有实施的想法。
- 与研究论断无关的调试历史。
- 未经测试却被描述成严格比较的备选方法。
- 仅为了展示“考虑过很多方案”而加入的解释。

论文应呈现方法及其被评价所必需的依据，而不是作者形成方法的全部思考过程。

## 6. 论断强度与常用表达

表达必须与认识和证据强度匹配。

| 表达功能 | 可采用的表述 |
|---|---|
| 直接观察 | “结果显示……”“测得……为……” |
| 有范围限制的实验发现 | “在本文测试条件下，结果表明……” |
| 谨慎解释 | “这一现象可能与……有关” |
| 比较 | “在相同评价条件下，与……相比……” |
| 文献综合 | “已有研究主要分为……”“这些研究在……方面存在差异” |
| 局限 | “当前评价仅覆盖……”“该结论尚未在……条件下得到检验” |
| 理论推导 | “在假设 A 和 B 成立的条件下，可以推出……” |
| 假设 | “本文提出……假设；该机制仍需进一步检验” |
| 贡献 | “本文构建/评价/识别了……”并具体说明对象 |
| 未来工作 | “后续研究应在……条件下进一步评价” |

没有依据时，不得使用“证明”“显著”“最优”“普适”“鲁棒”“安全”“可靠”“首次”等强表述。

### 6.1 保护论断强度，避免防御性写作

需要区分**基于证据的谨慎表达**与**防御性写作**。当证据、研究设计、假设或测试范围确实要求限定时，谨慎表达是必要的；如果缺少这些依据或读者理解上的实际需要，却额外添加模糊措辞、免责声明、自我否定、重复局限或假想审稿意见，就可能构成防御性写作。

新增或保留一项限定时，先检查：

1. 哪项具体证据、研究设计、假设或测试边界要求这项限定？
2. 它是否会实质影响读者对论断、有效性或可复现性的理解？
3. 相关信息是否已经在其他位置清楚说明？
4. 能否直接、正面地说明研究范围，而不是使用宽泛的否定式免责声明？

如果无法指出具体理由，就不要新增该限定。不能仅因为审稿人可能询问论文没有声称覆盖的其他场景，就把有证据支持的发现改成试探性判断。反过来，也不能为了让论文显得更有信心而删除真实局限。

对于重要论断，应将正式稿与写作前研究档案中的批准表述或论断强度基准进行对照。可将实质性变化标记为：保留、强化、收窄、弱化、撤回或新增限定。任何弱化、收窄、撤回或新增限定都必须注明证据及必要性。如果证据不支持这种变化，就保留有依据的原论断；如果证据确实要求调整，且变化影响中心论点或主要贡献，应先取得用户确认，并更新研究档案和论点—证据矩阵。

审稿意见应先作为独立的问题清单处理。逐项核验其事实性、相关性、重要性和证据依据；只有必要的修正或澄清才进入正文，审稿回复专属事项不必写入论文，无依据或不适用的意见应明确标记。真实局限应在最相关的章节集中说明，不要在全文反复添加免责声明。

示例：

**有证据支持的发现——保留其强度**

> 在本文测试条件下，方法 A 将验算通过率由 60% 提高至 85%。

如果论文没有声称该方法适用于所有桥型，就不应自动改成“方法 A 可能提高了验算通过率”，也不必额外附加一段关于所有未测试桥型的免责声明。

**真实研究边界——准确说明**

> 本研究在本文设定的设计范围内，对三种桥梁构型进行了评价。

当这确实反映实际评价范围时，这种表述能够提供具体信息，比“该方法未必适用于所有可能场景”之类的宽泛免责声明更有价值。

如果没有经批准的论断基准或早期草稿，不得声称论文相对于不可见的原文被弱化。仍可根据现有证据和论文自身声明的研究范围，检查最终文本中是否存在无依据、重复或比例失当的限定。

## 7. 中文学术表达示例

### 直接陈述研究内容

较弱：
> 本研究并不是简单地将人工智能技术应用于工程领域，而是构建了一种全面、系统且具有创新性的智能化研究框架。

更好：
> 本研究构建了一个由条件生成模型、参数化结构生成器和有限元评价模块组成的桥梁方案生成流程。

### 聚焦具体问题

较弱：
> 随着人工智能技术的不断发展，传统桥梁设计方法面临新的机遇和挑战。

更好：
> 现有参数化设计流程通常依赖预设结构形式和人工调整参数，难以直接生成满足多项工程约束的完整结构方案。

### 基于证据报告结果

较弱：
> 该方法显著提升了模型性能，具有较好的应用前景。

更好：
> 在相同测试条件下，采用该反馈策略后，有限元验算通过率由 X% 提高至 Y%。该结果支持其在当前测试范围内改善结构可行性生成的判断。

只有在实际数值已核实后，才能替换 X 和 Y。

### 避免无依据的泛化

较弱：
> 该方法具有良好的泛化能力，能够适用于各类桥梁结构。

更好：
> 该方法已在本文覆盖的桥型和设计条件下完成验证。其在其他结构体系中的适用性仍需进一步评估。

### 避免无关的决策日记

较弱：
> 研究初期考虑了遗传算法、粒子群算法和多种神经网络，经过多轮分析后最终选择了当前方法。

更好：
> 本研究采用 X 方法建立……关系。该选择主要基于……，并通过……实验评估其有效性。

只有当选择理由和实验真实存在时，才使用后一种表述。

## 8. 术语和技术表达一致性

- 关键术语首次定义后全文保持一致。
- 除非概念确实等价，否则不得将相关概念当作同义词。
- 符号、下标、单位、变量名和缩写保持一致。
- 缩写首次出现时按目标期刊规范定义。
- 采用学科通行译名，不得为追求文采而自创非标准译名。
- 在学科语境中区分“可行性”“安全性”“可靠性”“稳健性”“效率”和“最优性”。

## 9. 图、表和公式的正文表述

- 正文应引出每幅图、每张表，并说明它支持的主要发现。
- 不要在正文逐格复述表格或逐点复述图中数值。
- 应说明关键趋势、比较、异常或含义。
- 图题应说明研究对象和展示内容；图注/表注应解释缩写和条件。
- 确保坐标轴、单位、图例、色标和样本量可以理解。
- 没有数据或理论支持时，不得仅凭图形推断作用机制。

## 10. 英文学术论文表达

用户要求英文论文时：

- 优先采用清晰直接的主谓结构。
- 主动语态和被动语态根据学科及期刊惯例选择，不强制使用被动语态。
- 避免将中文修辞结构逐词翻译成英文。
- 证据有限时采用审慎措辞。
- 根据功能保持时态一致：已有知识、已完成方法、观测结果和解释分别处理。
- 使用目标期刊要求的术语和拼写体系。

## 11. 可参考的表达资源

以下资源用于学习表达功能，不是要求机械套用或复制：

- 曼彻斯特大学 Academic Phrasebank：用于理解引入研究、报告结果、讨论发现和表达审慎等学术交际功能。
- George D. Gopen 和 Judith A. Swan，1990 年发表的 “The Science of Scientific Writing”：关于读者预期、句首主题位置、句末强调位置和信息流。
- 目标期刊现行投稿指南：期刊特定规范的最终依据。

不得大段复制受版权保护的表达资源。应理解其表达功能，再结合真实研究撰写原创文本。
